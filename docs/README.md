# 项目文档地图与治理规则

> 本文件是 `docs` 的唯一导航入口。复制模板后删除不适用的占位说明，但保留目录职责、状态和替代关系。

## 1. 文档分层

### 项目级长期事实

- `技术文档/00-项目概述_TEMPLATE.md`：目标、范围、参与者、环境和仓库结构；
- `技术文档/01-术语数据与外部协议_TEMPLATE.md`：统一词汇、数据语义、外部接口和兼容约束；
- `技术文档/02-现有系统架构_TEMPLATE.md`：重构或开发前的真实基线；
- `技术文档/03-目标系统架构_TEMPLATE.md`：稳定目标、分层、依赖方向和演进路线；
- `技术文档/系统全链路架构与边界_TEMPLATE.md`：跨模块端到端统一事实入口；
- `使用与维护/系统全链路使用与维护_TEMPLATE.md`：配置、启动、验证、诊断、恢复和回滚入口。

### 任务级可追溯证据

- `技术文档/程序设计/TASK-程序设计_TEMPLATE.md`；
- `修改记录/CHANGE-修改记录_TEMPLATE.md`；
- `测试与验收/TEST-测试与验收_TEMPLATE.md`；
- 具体任务的需求文档；
- 必要时的 ADR、迁移、兼容、安全、性能和发布文档。

## 4. 状态与权威性

每份文档顶部标记：`Draft / Approved / Implementing / Completed / Superseded / Archived`，并记录负责人、执行人、对应任务、版本和最后核对日期。

- 同一事实只保留一个权威入口，其他文档使用链接引用；
- 全链路文档统一跨模块事实，模块文档补充内部细节；
- 修改记录描述“改了什么和为什么”，测试记录描述“如何证明”；两者不能相互替代；
- 发布说明面向版本消费者，不替代内部修改记录；
- 文档过期时注明替代文件和生效提交，不删除历史。
