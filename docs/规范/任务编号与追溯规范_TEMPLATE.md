# 任务编号与追溯规范模板

状态：待目标项目审核。已有编号不得直接按本模板重编；先盘点原编号、任务登记、历史提交和验收。

任务号标识业务范围，Session标识会话顺序，优先级标识排期，阶段/批次标识实施拆分，版本标识交付。它们不能互相代替，也不能沿排期继承前一任务的授权或验收。

| 候选前缀 | 职责 |
|---|---|
| FT | 独立新增功能 |
| RF | 行为保持的结构重构 |
| CH | 修复及维护变更 |
| TS | 独立测试任务 |
| RL | 独立发布任务 |

前缀、位数及分配方式须结合项目审核；推荐前缀内递增，预留、批准、实施和验收状态单列，不复用已分配身份。任务登记至少包含任务号、类别、标题、主记录、审核状态、依赖、验收入口与提交条件。纠正归属时保留旧号、来源、失败及撤回事实。

Git提交type与任务号是两个维度，格式及语义只在[Git提交信息规范](Git提交信息规范_TEMPLATE.md)维护，不能依据type改变需求归属。同一任务可有需求设计、实现、测试和文档等提交。
