# Git提交信息规范模板

状态：待目标项目审核；已有规范时以适用现行规范为准，不并行建立第二套规则。

推荐格式：`type(scope): [TASK-ID] 简明说明`。type描述本次提交的变更性质：feat新增能力，fix修复，refactor行为保持的结构调整，docs文档，test测试，build构建，ci流水线，chore其他维护。scope标识模块，TASK-ID引用业务任务，不随提交type改变。

例如独立FT任务的设计可使用docs、测试可使用test；不能据此改归文档任务或独立测试任务。提交按职责边界拆分，避免夹带其他任务、用户差异、个人配置、业务样本和构建产物。

提交前核对授权与审核条件、暂存范围、需求设计及验收证据、兼容边界、敏感信息和文档导航。未达到阶段门禁的内容留在工作区；不以构建通过代替人工验收，不通过改写历史隐去失败或撤回事实。
