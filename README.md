# AI Agent 项目开发模板

用于初始化项目的工程规范、任务工作流、文档地图和本地Session交接。模板不代表需求已批准、阶段已验收，也不自动授予提交、发布或外部写入权限。

## 使用顺序

1. 阅读[项目级初始化规范](CODEX_AGENT_INIT.md)及[工程文档地图](docs/README.md)，结合目标项目的真实规则调整，保留审核状态。
2. 使用[任务初始化模板](Session%20Init/SESSION_INIT_TEMPLATE.md)登记任务身份、需求、设计、授权和验证门禁。
3. 将实际Session资料置于目标项目Git忽略的目录，并确认未被跟踪；从[唯一线性索引模板](SESSION_README_TEMPLATE.md)建立README。
4. 切换时使用[交接模板](Session%20Switch/SESSION_SWITCH_TEMPLATE.md)，结束后按[归档模板](Session%20Archive/SESSION_ARCHIVE_TEMPLATE.md)维护来源和替代关系。

复制模板时使用占位符；真实个人路径、账号配置、样本与客户资料只填写到适当的本地文件，不复制到本公开模板仓库。项目自己的工程事实进入需求、设计、验收、维护或版本记录，不以个人交接替代。

Session在项目内连续编号；换任务、从重构转开发、改主题均不重置。历史文件保留原名并映射原序号，README按数字顺序记录前一、后一、主题、路径和状态。新交接以结束的Session编号命名。

任务分类与身份参考[任务编号规范模板](docs/规范/任务编号与追溯规范_TEMPLATE.md)，提交格式单独参考[Git提交规范模板](docs/规范/Git提交信息规范_TEMPLATE.md)，采用前须与目标项目现行规范核对并审核。

## 版本边界

现场项目实施、联调验收与产品重构、功能开发等独立任务默认分开会话，使用各自适用规则和任务入口。发现将混用时，Agent必须先明确提醒，取得负责人对具体范围的明确授权后才执行；授权不得扩展到其他任务或操作。连续编号不代表连续混用，详见[任务隔离规则](CODEX_AGENT_INIT.md#51-独立任务与会话隔离)。

首个init提交保留原有22个模板文件；后续提交记录治理更新。原版中的项目示例仅是历史模板内容，不代表适用于其他项目。此仓库不包含本机全局AGENTS正文、实际Session记录或业务实现。
